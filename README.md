# Project Accountants Learning Platform - Frontend

React 19 · Vite 7 · TypeScript · Tailwind CSS 4 · MUI 9 (themed) · TanStack Query · React Router 7 ·
React Hook Form + zod.
Node 20.19+.

The UI reproduces the prototype's visual language - black sidebar, Poppins, square corners, uppercase tracked
micro-labels, stat cards with a coloured top border - and is responsive down to phone width (sidebar → drawer,
tables → cards, dialogs → full screen).

## Run

```bash
npm install
cp .env.example .env.local   # fill in VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY
npm run dev                  # http://localhost:5173 (backend must be running on :4000)
```

### Try it without Supabase (local demo mode)

```bash
# terminal 1 - in ../backend
npm run demo                 # real API on an in-memory database with the prototype's demo data
# terminal 2 - here
npm run dev:demo             # sign-in becomes a "pick an account" list
```

Demo mode only works on the dev server; production builds ignore it.

## Scripts

| Script                             | What it does                                                      |
| ---------------------------------- | ----------------------------------------------------------------- |
| `npm run dev` / `npm run dev:demo` | Dev server (normal / demo mode)                                   |
| `npm run build`                    | Type-check and build to `dist/` (each page is its own lazy chunk) |
| `npm test`                         | Component and unit tests (Vitest + Testing Library)               |
| `npm run typecheck`                | Type-check only                                                   |


## Forms

Every form uses **React Hook Form + zod**. Each feature keeps its schema next to it (`*.schema.ts`, e.g.
`features/learning-items/item.schema.ts`); the rules mirror the backend validators, which remain the real gatekeeper.
Shared rules and `applyServerErrors()` (puts the server's field errors next to the right input) live in
`src/lib/forms.ts`. Field components accept `ref`, so they work directly with `register()`.

## Notes

- The browser only uses Supabase for **sign-in**; all data goes through the backend API, which enforces permissions.
  Route guards in the UI are for convenience only.
- Server state lives in TanStack Query (cache keys include the selected learning year); UI state is local.
- "Export selection" in drill-down dialogs creates a CSV in the browser (formula-injection safe); full reports are
  Excel files generated by the backend.
